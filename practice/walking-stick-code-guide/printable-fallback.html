Code your walking stick

One program, three results

At your already-built walking stick

The sensor reads distance. Your program chooses a result. A valid near reading gives X and a sound. A valid farther reading gives a blank display and silence. An unusable reading gives ? and UNKNOWN.

Use Blocks view in your working MakeCode project. Follow this guide with the separate sound page.

Check: You will update one project and keep the built sensor wiring. Code panels show the same blocks in JavaScript; they are not a replacement sensor program.

Help if you get stuck

Keep the model on a table during tests. This is a classroom prototype, not tested mobility equipment.

Keep the 30 cm rule

In the existing sensor decision blocks

Check for a usable reading first. Then compare the distance with 30 cm. The symbol ≤ means less than or equal to, so exactly 30 cm counts as near.

Follow the arrows: failed reading → ?; usable reading at or below 30 cm → X; usable reading above 30 cm → blank.

Check: All three outcomes belong to the same loop that reads the sensor.

Help if you get stuck

Keep an existing correct decision. If it is missing, build the outer valid/invalid if first, then the ≤30 if inside its valid branch, using the checked sensor value.

Prepare the two message variables

In MakeCode · Variables and on start

A variable is a named box that remembers a value. stickStatus holds text. btConnected holds true or false to remember the connection.

In Variables → Make a Variable, create stickStatus and btConnected. In on start, set stickStatus to the text UNKNOWN and btConnected to the Logic value false. Add Bluetooth → start UART service.

Check: The on start block has both set blocks and one start UART service block. UNKNOWN means no usable result yet.

Help if you get stuck

For UNKNOWN, use a Text block and type the word in capitals. For false, use Logic, not a text block. Reuse any matching startup blocks already present. The download is a setup reference, not a complete sensor program.

Download Bluetooth setup reference
let stickStatus = "UNKNOWN"
let btConnected = false
bluetooth.startUartService()

Remember connection and disconnection

In MakeCode · Bluetooth events

An event runs when something happens. These two events remember when the website connects or disconnects. The sensor loop still controls the display.

From Bluetooth, add on bluetooth connected and put set btConnected to true inside it. Add on bluetooth disconnected; put set btConnected to false and set stickStatus to UNKNOWN inside it.

Check: Each event exists once. true means connected; false means disconnected.

Help if you get stuck

Do not put sensor reading or a second forever loop in these events. Remove old temporary connection-display animations if they cover the sensor warning.

bluetooth.onBluetoothConnected(function () {
    btConnected = true
})
bluetooth.onBluetoothDisconnected(function () {
    btConnected = false
    stickStatus = "UNKNOWN"
})

Add the farther message

In the existing valid, distance >30 cm branch

FAR means the latest valid measurement is farther than 30 cm. It does not prove a whole walking route is clear.

Add another set stickStatus to block inside the existing farther branch, beside clear screen. Put the text FAR in its value space.

Check: A valid farther reading selects FAR and clears the display.

Help if you get stuck

Keep this branch inside the valid-reading decision. A failed reading must not fall into FAR.

stickStatus = "FAR"
// Keep the existing clear-screen block in this branch.

Send after the fresh sensor decision

In the same sensor-reading forever loop

Use one sender in the same forever loop that reads the sensor. It must send after the whole near/far/failed decision, so it reports the newest result.

Remove the old distance: send blocks and any separate sending loop. After the complete sensor decision, add a Logic if with btConnected as its condition. Inside it, add Bluetooth uart write line with the stickStatus variable. Put one checked 500 ms pause after the if.

Check: The sensor read stays in place. Only NEAR, FAR or UNKNOWN is sent. The write line block adds the line ending for you.

Help if you get stuck

Do not add a new forever sender. 500 milliseconds is half a second. If the sensor loop already pauses, have your teacher keep one suitable pause instead of stacking waits. The website does not accept distance: numbers.

// Inside the EXISTING sensor loop, after its whole decision:
if (btConnected) {
    bluetooth.uartWriteLine(stickStatus)
}
