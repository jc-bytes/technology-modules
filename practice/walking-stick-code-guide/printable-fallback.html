Complete MakeCode JavaScript — ready to paste

Add the Bluetooth extension first. Replace the whole JavaScript editor with this code.

// Based on your HC-SR04 code, with your corrected pins: Trig P0, Echo P1.
// Add the Bluetooth extension before pasting.
let trigPin = DigitalPin.P0
let echoPin = DigitalPin.P1
let echoTime = 0
let distanceCm = 0
let stickStatus = "UNKNOWN"
let btConnected = false

function readUltrasonicDistance() {
    pins.digitalWritePin(trigPin, 0)
    control.waitMicros(2)
    pins.digitalWritePin(trigPin, 1)
    control.waitMicros(10)
    pins.digitalWritePin(trigPin, 0)
    return pins.pulseIn(echoPin, PulseValue.High, 25000)
}

bluetooth.onBluetoothConnected(function () {
    btConnected = true
})

bluetooth.onBluetoothDisconnected(function () {
    btConnected = false
    stickStatus = "UNKNOWN"
})

bluetooth.startUartService()

basic.forever(function () {
    echoTime = readUltrasonicDistance()

    // Reject missing echoes and readings outside about 2–400 cm.
    if (echoTime < 116 || echoTime > 23200) {
        distanceCm = 0
        stickStatus = "UNKNOWN"
        basic.showString("?")
    } else {
        // The original sensor code returns microseconds, not centimetres.
        distanceCm = echoTime / 58

        if (distanceCm <= 30) {
            stickStatus = "NEAR"
            basic.showIcon(IconNames.No)
        } else {
            stickStatus = "FAR"
            basic.clearScreen()
        }
    }

    // Send only the result of the fresh reading above.
    if (btConnected) {
        bluetooth.uartWriteLine(stickStatus)
    }

    basic.pause(500)
})

Inspect the on start stack

In Blocks · on start

on start runs once. Variables are named boxes: stickStatus stores a word and btConnected stores true or false. UART service prepares Bluetooth text messages.

Compare your on start stack with the real block image. Find trigPin P0, echoPin P1, stickStatus UNKNOWN and Bluetooth uart service.

Check: These blocks already came from the pasted program. No NEAR/FAR decision, UART write or repeating pause is inside on start.

Help if you get stuck

MakeCode hides default initial values in Blocks: echoTime and distanceCm begin at 0; btConnected begins false. The initial UNKNOWN is only the starting word. The forever stack later replaces it using a fresh measurement. UART service prepares sending; UART write line actually sends and belongs in forever.

Inspect the sensor-reading function

In Blocks · function readUltrasonicDistance

A function is a named set of instructions. This one sends a short trigger pulse and returns the length of the Echo pulse in microseconds, not centimetres.

Find the separate readUltrasonicDistance function. Follow Trig low, wait 2 microseconds, Trig high, wait 10 microseconds, Trig low, then pulse in on Echo with a 25000-microsecond timeout.

Check: The function uses trigPin P0 and echoPin P1. It returns an echo time; the distance conversion happens later in forever.

Help if you get stuck

A microsecond is one millionth of a second. The timeout limits how long pulse in waits; a missing pulse returns 0. The return may contain a grey JavaScript block showing pins.pulseIn(echoPin, PulseValue.High, 25000). That is expected; keep it unchanged.

Inspect the two Bluetooth events

In Blocks · two separate Bluetooth event stacks

An event runs when a connection changes. These events remember the connection state while the separate forever stack reads the sensor.

Find on bluetooth connected with set btConnected to true. Find on bluetooth disconnected with set btConnected to false and set stickStatus to UNKNOWN.

Check: Both event stacks match the image. They contain no sensor loop, near/far decision or sender.

Help if you get stuck

Check the invalid echo first

In Blocks · forever → first if

forever first calls the sensor function and stores its returned time in echoTime. The first if rejects an echo below 116 or above 23200 microseconds.

Find set echoTime to call readUltrasonicDistance. Follow the first if: echoTime < 116 OR echoTime > 23200. Inside it, find distanceCm 0, stickStatus UNKNOWN and show string ?.

Check: A missing echo returns 0 and enters UNKNOWN. This invalid branch runs before any near/far comparison.

Help if you get stuck

< means less than; > means greater than. OR means either condition is enough. The accepted echo interval is about 2–400 cm. distanceCm 0 here marks an unusable result; it is not a measured zero-centimetre obstacle. Do not move UNKNOWN to the end of a straight stack.

Follow a usable echo to NEAR

In Blocks · first if’s else → distanceCm ≤ 30

The outer else handles accepted echoes. It divides echoTime by 58 to estimate centimetres. A second if then checks whether that distance is at or below 30 cm.

In the outer else, find set distanceCm to echoTime ÷ 58. Follow the inner distanceCm ≤ 30 branch to set stickStatus NEAR and show icon X.

Check: Only an accepted echo can become NEAR. Exactly 30 cm belongs to this branch.

Help if you get stuck

÷ 58 converts this program’s raw echo time into centimetres once. ≤ means less than or equal to. The X is the No icon. Inspect the blocks already present; do not add a second conversion or another if.

Follow a usable farther echo to FAR

In Blocks · outer else → inner distance check’s else

The inner else runs only after the echo was accepted and the distance was found to be above 30 cm.

Find the else paired with distanceCm ≤ 30. Follow set stickStatus to FAR and clear screen.

Check: FAR gives a blank micro:bit display. The invalid-echo branch is separate and cannot become FAR.

Help if you get stuck

There are two different else branches. The outer else contains the conversion and whole near/far decision. This inner else contains only FAR and clear screen. Compare their nesting in the image.

Inspect the sender after the whole decision

In Blocks · bottom of the same forever stack

The sensor decision chooses one word first. A separate if then sends that word only when btConnected is true.

After the complete sensor if/else, find if btConnected with Bluetooth uart write line stickStatus inside. Find pause 500 after that if, still inside forever.

Check: There is one sensor loop and one UART write line. Sending is outside every result branch. The pause runs even when disconnected.

Help if you get stuck

Write line sends the chosen word with a line ending so the website can read a complete message. The 500-millisecond pause is half a second. No sender or loop pause belongs in on start. Do not append an old distance: sender.
