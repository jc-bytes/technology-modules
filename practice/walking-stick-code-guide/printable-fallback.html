Fill only the on start stack

Inside on start · not inside forever or an event

on start runs once. Bluetooth uart service prepares the message service. Bluetooth uart write sends a result and belongs later in forever.

Create stickStatus and btConnected in Variables. In on start, keep one set stickStatus to UNKNOWN, one set btConnected to Logic false and one Bluetooth uart service. Remove misplaced NEAR/FAR setters, extra UNKNOWN setters, all UART write blocks, send if blocks and loop pauses from on start.

Check: Keep any existing sensor setup. Startup has UART service, not UART write. The result choices and sending blocks will go in forever.

Help if you get stuck

A variable is a named box for a value. stickStatus holds text; use a Text block for UNKNOWN. btConnected holds true or false; use Logic false. If repairing the earlier straight stack, remove only the misplaced Bluetooth/result/send blocks. Keep the real sensor setup.

Build the two separate event stacks

Two separate top-level stacks · outside on start and forever

An event runs when something happens. These two events remember when the website connects or disconnects. The sensor loop still controls the display.

From Bluetooth, drag on bluetooth connected into an empty workspace area and put set btConnected to true inside it. Beside it, add on bluetooth disconnected with set btConnected to false and set stickStatus to UNKNOWN.

Check: Two separate event stacks look like the diagram. Neither event contains sensor reads, NEAR/FAR decisions or the send block.

Help if you get stuck

Add the near message

forever → usable-reading branch → distance ≤ 30 branch

An if/else chooses one path. The near result belongs inside the usable-reading path, where the checked distance is at or below 30 cm.

Inside the existing forever stack, find the usable-reading test and its distance ≤ 30 branch. Put set stickStatus to the text NEAR directly beside the existing X display.

Check: NEAR is nested inside both checks. It is not in on start. Exactly 30 cm belongs to this near branch.

Help if you get stuck

Keep the exact uppercase word. Use the existing near branch; do not add another sensor read for Bluetooth.

Add the farther message

forever → usable-reading branch → distance check’s else

This else belongs to the distance check. It runs only when the reading is usable and the distance is above 30 cm.

Inside the same usable-reading path, find the else paired with distance ≤ 30. Put set stickStatus to the text FAR beside the existing clear screen block.

Check: FAR is inside the distance check’s else. Do not put it after NEAR or outside the usable-reading test.

Help if you get stuck

Keep this branch inside the valid-reading decision. A failed reading must not fall into FAR.

Add the unusable-reading message

forever → failed-reading branch of the outer sensor test

The failed-reading branch is separate from both usable-distance branches. It must not fall through to FAR.

Find the failed-reading branch paired with the outer usable-reading test. Put set stickStatus to the text UNKNOWN beside the existing ? display.

Check: Each fresh reading selects only one result: NEAR, FAR or UNKNOWN. UNKNOWN does not sit after FAR in a straight stack.

Help if you get stuck

Use your existing checked validity rule. The diagram puts usable readings in if and failed ones in else. If your existing test is the other way round, keep its correct branch meanings. Never treat the older 50000 placeholder as a usable far distance.

Send at the bottom of forever

Inside the same forever · after the entire sensor if/else

The complete sensor decision finishes first. The send if is a separate block after that decision, still inside forever.

Keep the sensor read. Remove old distance: send blocks and any separate sending loop. After the whole sensor decision, add if btConnected with Bluetooth uart write line stickStatus inside it. Put one checked pause 500 after the send if.

Check: The send if is not inside NEAR, FAR, UNKNOWN or on start. The pause is inside forever but outside the send if, so it runs even when disconnected.

Help if you get stuck

Close the full sensor decision before placing the send if. Match the nesting in the diagram. Reuse one suitable existing pause with your teacher rather than stacking waits. Write line adds the line ending automatically.
