Start the message service

In MakeCode · on start

UART is a service for sending short text messages. Starting it makes this message channel available when the program starts.

Place Bluetooth → bluetooth uart service inside on start.

Check: The program starts the UART service once.

Help if you get stuck

Expand the Bluetooth category or its more section to find the UART blocks.

bluetooth.startUartService()

Start with an unknown result

In MakeCode · Variables and on start

A variable is a named place holding a value. status holds the message we will send. UNKNOWN means we have no usable sensor result.

Create status and set it to the text "UNKNOWN" in on start.

Check: status starts as text in uppercase.

Help if you get stuck

Use a text value with quotes in JavaScript. Do not type UNKNOWN as a variable name.

let status = "UNKNOWN"

Start disconnected

In MakeCode · Variables and on start

btConnected holds true or false. At startup the website has not connected yet.

Create btConnected and set it to Logic → false in on start.

Check: btConnected starts false.

Help if you get stuck

False is a Logic value. Do not use the text "false".

let btConnected = false

Notice a connection

In MakeCode · Bluetooth

An event runs when something happens. This event runs when the micro:bit gets a Bluetooth connection.

Add on bluetooth connected and put set btConnected to true inside it.

Check: The flag becomes true when a device connects.

Help if you get stuck

This means a device connected. It does not confirm a sensor reading or prove which person is using the device.

bluetooth.onBluetoothConnected(function () {
    btConnected = true
})

Notice a lost connection

In MakeCode · Bluetooth

When the connection closes, the program must stop sending and stop keeping an old result as its starting state.

Add on bluetooth disconnected with btConnected set to false and status set to "UNKNOWN".

Check: A lost connection clears the connection flag and old status.

Help if you get stuck

Keep these assignments in this event. They do not change the sensor wiring.

bluetooth.onBluetoothDisconnected(function () {
    btConnected = false
    status = "UNKNOWN"
})

Make A mean near

In MakeCode · Input

The buttons are temporary pretend inputs. NEAR is the exact message for a usable distance at 30 cm or nearer.

Add on button A pressed and set status to "NEAR" inside it.

Check: Pressing A selects the NEAR message.

Help if you get stuck

This changes text only. It does not take a sensor measurement.

input.onButtonPressed(Button.A, function () {
    status = "NEAR"
})

Make B mean farther

In MakeCode · Input

FAR means a usable sensor reading above 30 cm. It never means every possible obstacle has been checked.

Add on button B pressed and set status to "FAR" inside it.

Check: Pressing B selects the FAR message.

input.onButtonPressed(Button.B, function () {
    status = "FAR"
})

Make A+B mean unknown

In MakeCode · Input

UNKNOWN is different from FAR. A missing or unusable measurement cannot say that the area is clear.

Add on button A+B pressed and set status to "UNKNOWN" inside it.

Check: Pressing A and B together selects UNKNOWN.

input.onButtonPressed(Button.AB, function () {
    status = "UNKNOWN"
})

Send only while connected

In MakeCode · Basic and Logic

Forever repeats its instructions. The if block allows a send only when btConnected is true.

Place if btConnected then inside a forever block.

Check: The forever loop contains a connection check.

Help if you get stuck

Keep this sending loop separate from the sensor loop when you add it later.

basic.forever(function () {
    if (btConnected) {
        // Put the send block here next.
    }
})

Send one whole message

In MakeCode · inside if btConnected

The website reads one message per line. uart write line adds the line ending for you.

Place Bluetooth → uart write line with status in its text slot.

Check: The selected message is sent as a complete line.

Help if you get stuck

Use uart write line, not uart write string. Do not add extra labels, numbers or spaces to the status text.

bluetooth.uartWriteLine(status)

Wait half a second

In MakeCode · forever, below the whole if block

500 milliseconds is half a second. Repeating the message lets the website notice when messages stop arriving.

Place Basic → pause 500 outside the if block, at the bottom of forever.

Check: The loop sends at roughly half-second intervals while connected.

Help if you get stuck

The pause stays outside if so the loop also waits when disconnected. This heartbeat confirms recent messages, not a fresh sensor measurement by itself.

Complete button rehearsal reference, .ts
basic.forever(function () {
    if (btConnected) {
        bluetooth.uartWriteLine(status)
    }
    basic.pause(500)
})

Send after the fresh decision

In MakeCode · end of the original sensor-reading forever loop

Put sending in the same loop as the sensor decision. If that loop stops producing results, the website will stop hearing messages and show unknown.

Add the checked if btConnected → uart write line status stack after the complete decision, followed by pause 500.

Check: One sensor loop reads, checks validity, selects status and display, sends that status if connected, then waits.

Help if you get stuck

Do not restore the separate rehearsal sender. Put sending outside every near, far and invalid branch so every completed reading can be reported. Keep a checked sensor timing requirement; ask your teacher to reconcile an existing pause instead of stacking duplicate waits.

// After the EXISTING fresh sensor read, validity check,
// status assignment and display decision, in the SAME loop:
if (btConnected) {
    bluetooth.uartWriteLine(status)
}
basic.pause(500)
