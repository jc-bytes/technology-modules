Input and output

Add a lunch choice

Your app will confirm the meal the user selects.

Open the same LunchApp and run its Confirm button.

A selector and a value

MealSpinner offers Rice and Vegetables.

selected_meal holds the choice used by Confirm.

The label displays the stored choice.

The meal selector

In Designer, add a Spinner. Rename it MealSpinner.

Set ElementsFromString to Rice,Vegetables.

The comma separates the two choices.

A variable starts with a value

In Variables, add initialize global name to.

Rename name to selected_meal. Connect an empty Text block.

The value can change while the app runs.

The current selection

Inside ConfirmButton.Click, set global selected_meal to MealSpinner.Selection.

Selection gives the food currently selected in the Spinner.

Each click stores the current food.

The confirmation message

After storing the selection, set ResultLabel.Text to join.

First part: the text You chose: followed by a space.

Second part: get global selected_meal.

Why the order matters

Choose Vegetables. Click Confirm.

First the variable holds Vegetables.

Then the label reads that value and shows You chose: Vegetables.

Displaying first could show the previous choice.

Rice together

Expected: You chose: Rice.

Point to the selector, stored value and message.

Two independent checks

Choose Vegetables and click Confirm. Read the result.

Choose Rice and click Confirm again. Read it again.

The message must follow the current choice.

A fixed message bug

If both choices show Rice, inspect the message block.

A fixed Rice text block always says Rice.

Use get global selected_meal in join, then repeat the failed test.
